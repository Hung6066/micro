# Harbor K3s Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy self-hosted Harbor behind HTTPS Ingress and use it as the signed production image registry.

**Architecture:** Harbor runs in its own namespace with persistent local-path storage. An Ingress exposes `harbor.his-hope.local`; robot credentials provide pull-only K3s access. Release images are pushed by digest, signed by Cosign, verified, and then referenced by production Kustomize.

**Tech Stack:** Harbor Helm chart, K3s Ingress, local-path PVCs, Docker/OCI registry, Cosign, Kustomize.

## Global Constraints

- Do not commit Harbor passwords, robot tokens, Cosign private keys, or registry TLS private keys.
- Do not disturb Vault HA, SPIRE, or CNPG resources.
- Do not mark production images signed until `cosign verify` succeeds.
- Use exact digest-pinned image references in production.
